# Расширенный технический радар «Будущее 2.0»

Радар включает технологии и архитектурные паттерны. Кольца:

| Кольцо | Значение |
|--------|----------|
| Adopt | Целевой стандарт: внедряем в промышленную эксплуатацию во всех новых решениях |
| Trial | Пилот: проверено на пилотных доменах, внедряем ограниченно с оценкой результата |
| Assess | Оценка: изучаем, готовим эксперименты, решение не принято |
| Hold | Остановить: не используем в новых разработках, существующее — мигрируем/выводим |

## Квадрант 1. Архитектурные паттерны и практики

| # | Паттерн/практика | Статус | Обоснование и действия |
|---|------------------|--------|------------------------|
| 1 | Data Mesh | Adopt | Целевая операционная модель: домены владеют дата-продуктами, платформа — self-service. Закреплено роадмапом (задание 5) и архитектурой (задание 3) |
| 2 | Event-Driven Architecture | Adopt | Ослабление связанности, near-real-time; обоснование vs Camel/DWH — задание 4 |
| 3 | Self-service BI | Adopt | Бизнес-цель кейса: портал самообслуживания, конструктор отчётов без участия центральной команды |
| 4 | Data Contracts + Schema Registry | Adopt | Безопасная эволюция событий, снижение риска A4 (контракты); обязательны с пилота |
| 5 | Lakehouse (open table formats) | Trial | Сотни ТБ: горячее/холодное разделение (ClickHouse + S3/Iceberg); пилот на витринах.patient-flow |
| 6 | CQRS / Event Sourcing | Assess | Точечно в финтехе (аудит транзакций); полная ES-модель избыточна для большинства доменов |
| 7 | Data Fabric (централизованная интеграция) | Hold | Противоречит децентрализации Data Mesh; не принимаем как целевой паттерн |

## Правила работы с радаром

1. Пересмотр — раз в квартал платформенной командой совместно с Data Product Owner'ами
   (синхронно с риск-комитетом задания 3).
2. Переход Assess → Trial — только через пилот с измеримым критерием успеха.
3. Статус Hold не означает немедленный демонтаж: для легаси действует план-график вывода
   (роадмап, этап 3) и ACL-мосты.
4. Новые инструменты по умолчанию начинают с Assess; исключения — технологии, уже
   закреплённые архитектурой (Kafka, ClickHouse, Terraform, K8s).
